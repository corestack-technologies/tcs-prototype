# TCS v1 Domain Model

TCS Prototype v1 production handoff. Requirements describe the approved build contract, not infrastructure already delivered.

These are conceptual entities, not final tables. Prototype nesting or derived records do not require the same production storage shape. Organization → Group → Cycle → Round is the financial context; Member remains a platform identity, and membership links the two. Each financial event retains its originating context even after closure or rollover.

| Entity | Responsibility | Identifiers / relationships | State fields | Audit expectations |
| --- | --- | --- | --- | --- |
| Member | Platform individual; not owned by an Organization | memberId; profile, KYC, memberships and optional owned Organization | active/restricted/suspended/closed; contacts; onboardingComplete | Identity/contact and eligibility changes; retain closure/default history |
| Client Profile | Contact, personal and bank information | memberId; KYC submission snapshots; validated beneficiary bank | Draft completeness; contact verification; bank resolution | Do not rewrite submitted identity or bank snapshots |
| Verification / KYC | Evidence and independent decision | verification/submission ID, memberId, document IDs, review ID | required/pending/information-required/rejected/verified | Submitted evidence, information responses, reviewer, reason and decision |
| Organization | Tenant operated by one eligible Owner | organizationId; ownerMemberId; Groups; approved application | draft through approved/active/restricted/suspended/closure-pending/closed | Ownership, activation, restrictions, closure clearance; no normal transfer |
| Organization Application | Application and submitted facts | application ID; organizationId; owner snapshot; source review | draft/submitted/pending/information-required/approved/declined | Immutable submission, responses, deciding authority |
| Settlement Account / Change | Reviewed destination for provider settlement | organizationId, changeId; prior/proposed account snapshots | pending/approved/information-required/rejected; effectiveAt | Resolution, confirmation, request/approval/effective times |
| Group | Long-lived thrift arrangement | groupId; organizationId; currentCycleId; Cycle history | Lifecycle derives from Cycles and termination record; visibility | Creation and termination; retain cancelled/closed records |
| Cycle | One payout rotation with accepted terms | cycleId; groupId; number; snapshot; previous Cycle link | draft/activated/cancelled/completed/completed-with-recovery/force-closed | Activated terms, roster, order; financial commencement; completion reason |
| Round | One scheduled collection/payout interval | roundId; cycleId; position; beneficiaries | Upcoming/Open/Due/Grace/Late timing; independent resolution | Original schedule/timezone and generated/resolved markers |
| Position | Ordered full slot or paired halves | cycleId + position number; memberId/fraction holdings | Proposed/finalized assignment; 1 or 0.5 only | Acceptance-relevant order/size; outgoing and replacement history |
| Membership | Member participation in a particular Cycle | memberId + cycleId; Organization/Group context; Position holdings | Participant approval plus separate acceptance and exit/replacement state | No deletion after commencement; retained historical participation |
| Join Request / Invitation | Request for entry or invitation to participate | requestId; memberId; groupId/cycleId; source invitation/public-request | pending/approved/rejected | Decision actor/reason, eligibility and original request; legacy UI requires real connection |
| Commitment | Explicit acceptance of material terms | acceptance ID; participant/memberId; cycleId; revision; terms fingerprint | Current or invalidated by material revision | Who accepted which terms when; no silence-as-acceptance |
| Obligation | Generated required and optional position components | obligationId; componentId; memberId; cycleId; roundId | Unpaid/Partially satisfied/Satisfied; optional not required; independent timing | Generated amount/due date; links to allocations and Recovery |
| Payment Attempt | Initiation and retry identity | attemptId; Member/Organization/Group/Cycle/Round; expected amount | created/awaiting-payment/provider-pending/confirmed/failed/expired | Intent, target, provider reference and every status fact |
| Contribution / Payment | Trusted received transaction facts | transactionId; provider + reference; attemptId; tenant/currency | confirmed; separate allocation and settlement axes | Provider success, actual received time, effective business time; duplicates/conflicts |
| Payment Allocation | Recognized satisfaction of a debt component | allocationId; transactionId; obligation/component; amountMinor | required/optional target; timeliness; source | Original recognition timestamp and amount; no repeated consumption |
| Advance Reservation | Received funds held for an unopened eligible Round | transactionId; cycleId/roundId; memberId; target intent | awaiting-round-opening; released or exception | Production explicit reservation and release allocation; prototype derives hold from transaction |
| Payment Exception | Received funds that cannot allocate normally | exceptionId; transactionId; linked Operations case | open source exception; independent case handling state | Actual received amount and mismatch/ineligibility/conflict; no fake failure |
| Provider Settlement | Provider settlement facts and expected matching | provider settlement ID; organizationId; transaction links | pending/delayed/partial/settled/exception expectations; matched/variance record | Gross, fees, deductions, net, links and corrections retained |
| Payout | Beneficiary obligation and response aggregate | payoutId; group/cycle/round; member/position/fraction | ready/instruction-prepared/partially-paid/awaiting-confirmation/disputed/completed variants/exception | Entitlement/calculation and separate transfer/evidence/outstanding |
| Payout Instruction | Bank and calculation snapshot used for transfer | instructionId; payoutId; bank snapshot | current/stale | Preparation and invalidation reasons; old instruction preserved |
| Payout Installment | One externally executed transfer | installmentId; instructionId; reference; evidence ID | awaiting-confirmation/member-confirmed/window-elapsed/disputed | Owner, transfer time, recorded time, partial reason/plan, recipient action |
| Organization Fee | Agreed payout fee and installment recognition | cycle terms; payout/installment recognition key | Agreed, recognized; separately identified adjustment requirement | Original posting and later outcome; no individual commercial waiver |
| TCS Revenue Share | Receivable on recognized Organization Fee | receivableId; installment; paymentId; unique reference; account snapshot | due/overdue/restricted/settled; payment awaiting-confirmation/exception/confirmed | Original amount/rate, transfer evidence and independent TCS receipt confirmation |
| Penalty Accrual | Simple required-principal daily monetary charge | accrualId; componentId + local date; obligation/member/cycle | ACCRUED; separate waivers and recovery allocations | Rate, principal basis, rounded kobo, businessAt and recordedAt immutable |
| Penalty Waiver | Audited reduction of unpaid penalty only | waiverId; accrualId; actor | Posted reduction; original charge retained | Amount, authority, reason and actual time; self-benefit prohibited |
| Default | Historical qualified Post-Payout Default fact | defaultEventId; member/obligation/cycle; recoveryId | POST_PAYOUT_DEFAULT retained even after clearance | Recognized payout receipt, thresholdAt and outstanding principal at detection |
| Recovery | Retained debt and clearance review | recoveryId; obligation/penalty links; receipt/allocation IDs | open/awaiting-review/resolved; restriction and review axes | Principal-first oldest-due allocation; dated receipts; excess exception; historical default |
| Exit / Exit Settlement | Departure before receipt and Organization liability | exitId; member/cycle; settlement/confirmation IDs | requested/approved/declined; settlement due/resolved | Recognized contribution, due timing, settlement evidence; no fake Member default |
| Replacement | Controlled handover to incoming Member | replacementId; exitId; outgoing/incoming IDs; Positions | proposed/awaiting-regularization/effective | Terms consent, regularization and effective date; original contributions retained |
| Amendment / Continuation | Controlled term change or new Cycle | amendmentId; cycleId; affected Members; priorCycleId | Consent/review/application states; rollover/fresh new draft | Reason, proposed/prior terms, each consent and independent review |
| Force Close / Termination | Exceptional Cycle closure versus permanent Group closure | requestId; cycle/group; source case | pending-tcs-review/approved/rejected/information-required; separate terminated | Balance snapshot, liability/absorption, evidence and approving authority |
| Dispute / Appeal | Evidence-led contested payout or liability | disputeId; installment/exit; evidence/request/resolution IDs | investigation/appeal-available/appeal-pending/final/exceptionally-reopened | One appeal, independent reviewer, evidence windows and immutable prior outcomes |
| Restriction | Source-linked limitation on new activity | restrictionId; Member/Organization; sourceCaseId | active/released; new-activity/suspension/post-payout-default | Scope, authority, reason, release; independent restrictions survive |
| Operations Case | Operational projection over a source problem | caseId + source ID/type; assignment/review IDs | New/Assigned/In Review/Awaiting Information/Awaiting External Action/Awaiting Approval/Escalated/Resolved/Closed | Triage separately from source decision; authoritative source outcome and actor snapshot |
| Internal User | Identified Internal actor | userId; roleIds; session IDs | Pending/Active/Suspended/Deactivated; independent lock | Creation, lifecycle and administrative reason |
| Role / Permission | Exact capability grants | roleId; recognized permission key | Active/inactive role; catalogue-recognized keys only | Before/after grants, actor authority, self-escalation prevention |
| Session | Authenticated session to be made durable in production | sessionId; userId; revocation reference | Active/Expired/Revoked | Issuance, expiry, activity, revocation; prototype session is simulated |
| Security Event | Security-relevant observed/admin event | eventId; userId/sessionId; Access audit correlation | Result/type, lock context | Actual time and authorized action; redact sensitive payloads |
| Runtime Control | Explicit supported configuration | key CLIENT_VERIFICATION_MODE; revision; changeId | EMAIL/PHONE/BOTH | Before/after, reason, actor, environment and actual time |
| Business Date Change | Non-production effective clock adjustment | changeId; revision; environment | REAL_TIME/CONTROLLED; prior/new date | Protected history boundary; actual time separate from target date |
| Scheduled Process Run | One lifecycle evaluation and retry lineage | runId; definition key; retryOf; step key | RUNNING/COMPLETED/COMPLETED_WITH_NO_CHANGES/PARTIAL_FAILURE/FAILED | Authority, environment, effective date, actual start/end, counts/errors |
