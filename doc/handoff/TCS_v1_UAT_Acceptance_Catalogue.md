# TCS v1 UAT Acceptance Catalogue

Production handoff for frozen TCS Prototype v1. No production implementation is performed in Stage 8.

These 26 scenarios are production acceptance requirements, not a claim that production integrations were tested. Use isolated UAT identities, provider test modes and a resettable database. For each record source IDs, actor, inputs, expected/actual outcome, audit references and evidence. Test the success path and stated denied/retry boundary. Existing tests/*.test.mjs named below provide domain regression evidence; production must add persistence, API, browser and adapter evidence.

| ID | Journey | Given / when | Then / required acceptance | Prototype evidence |
| --- | --- | --- | --- | --- |
| U01 | Registration / onboarding | New identity; selected contact mode; complete registration and required contact challenges | Own profile persists across restart; required channels enforced; invalid/expired/reused code rejected; demo persona cannot authenticate | clients; settings |
| U02 | KYC / information response | Complete eligible profile; submit evidence; reviewer requests info then decides | Original submission retained; response linked; Member cannot approve own KYC; unauthorized reviewer denied | clients; operations-decisions |
| U03 | Organization approval / ownership | Verified eligible Member submits one application and completes approved setup | Approval distinct from activation; second owned Organization denied; settlement snapshot retained; cross-tenant read denied | organizations |
| U04 | Group setup / recruitment | Owner drafts Group, receives join request, invites and approves participants | Legacy discovery is connected to actual request/membership in production; public/private eligibility respected; active Member cannot be deleted | groups |
| U05 | Positions / reconfirmation | Assign full and paired half Positions, multiple holdings within policy; change accepted material term | Invalid fraction/capacity rejected; affected acceptance invalidated; current order and terms explicitly reconfirmed | groups; rounds |
| U06 | Activation / cancellation | Try activation with incomplete readiness, then activate ready draft; generate first obligation | Incomplete activation rejected; snapshot locked; cancellation allowed before financial commencement and denied afterward | groups; rounds; lifecycle |

| U18 | Early Exit / replacement / settlement | Before receipt request exit, accept replacement terms, regularize and settle outgoing Member | History retained; effective handover guarded; Organization owes Exit Settlement; no replacement after payout; Owner self-benefit denied | lifecycle; operations-decisions |

| U21 | Access / security | Assign/edit roles; attempt self-escalation and last-admin removal; revoke session/unlock | Exact permissions and active unlocked user enforced server-side; indirect self-escalation rejected; audit authority retained; Access not Operations/Settings | access; security |

| U23 | Process concurrency / retry | Run lifecycle catch-up; simulate failure after partial success; concurrent worker and retry | Durable partial results; linked authorized retry; no duplicate financial effects; run-only reviewer cannot retry; scenario clock excluded; alerts/history correct | processes; financial-regularization |

| U26 | Responsive / network / persistence | Use representative Member/Owner/Internal journeys on phone/tablet/desktop with slow/offline/expired session | Readable forms/tables and focused dialogs; meaningful retry/error; no double submit; restart retains source data; no cross-tenant cache leakage | design-foundation and render contracts; real-browser/device UAT remains required |

A slice passes only when its positive and authorization/financial invariants pass through the real API and database, and relevant reports agree. A successful HTTP shell response is not UAT. Production pilot approval also requires unresolved provider/legal/security readiness decisions to be closed.
